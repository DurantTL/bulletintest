# CLAUDE.md

## Project Overview

**Boletín Automático** — An automated church bulletin generator for Van Buren SDA Church. A secretary emails a Word document (`boletin.docx`), which is automatically parsed into a styled HTML bulletin and deployed to GitHub Pages.

**Workflow:** Secretary sends `.docx` via email → Gmail filter → Make.com webhook → GitHub Actions → `build.js` parses docx → `index.html` generated → GitHub Pages deployment.

## Repository Structure

```
bulletintest/

├── template.html        # HTML template with {{placeholder}} syntax

├── package.json         # Node.js project config (single dependency: mammoth)
```

## Tech Stack

- **Runtime:** Node.js 20.x
- **Language:** JavaScript (CommonJS)
- **Dependencies:** `mammoth` (^1.6.0) — converts `.docx` to plain text
- **Deployment:** GitHub Pages via `peaceiris/actions-gh-pages@v3`
- **Package manager:** npm

## Commands

| Command | Description |
|---------|-------------|
| `npm install` | Install dependencies |
| `npm run build` | Run the bulletin parser (`node build.js`) |

There are no test, lint, or formatting commands configured.

## Build Process

`build.js` performs these steps:

1. Reads `boletin.docx` using mammoth (converts to plain text)
2. Normalizes Spanish text (accent-insensitive matching)
3. Parses in multiple passes:
   - **Pass 1:** Extract date via regex
   - **Pass 2:** Find pastor name in header
   - **Pass 3:** Find weekly verse
   - **Pass 4:** Parse sections (Escuela Sabática, Culto Divino, Anuncios)
4. Replaces `{{placeholders}}` in `template.html` with extracted values
5. Writes output to `index.html`

## Key Architecture Decisions

### Parsing Strategy
- The parser works on **plain text** extracted from `.docx` (not HTML or table structures)
- All extraction is **line-by-line** with keyword detection and lookahead patterns
- Spanish accents are normalized for comparison using Unicode NFD decomposition

### Template System
- Simple `{{key}}` placeholder replacement via regex
- No template engine; all logic lives in `build.js`
- 50+ template fields organized by section prefix:
  - `ss_*` — Escuela Sabática (Sabbath School)
  - `cd_*` — Culto Divino (Divine Service)
  - Suffixes: `_who` (person), `_hymn` (hymn number), `_ref` (scripture reference)

### Styling
- Mobile-first responsive design with CSS custom properties
- Breakpoint at 768px (single column → two-column grid)
- Brand colors: `--brand: #bf630e` (orange), `--accent: #0b6a53` (green)

## Code Conventions

- **File naming:** lowercase (build.js, template.html, boletin.docx)
- **Constants:** UPPER_SNAKE_CASE (`INPUT_FILE`, `TEMPLATE_FILE`, `OUTPUT_FILE`)
- **Variables/fields:** camelCase for JS, snake_case for template field names
- **Comments:** English in code, Spanish in user-facing content (README, template)
- **No semicolons policy is NOT enforced** — semicolons are used throughout

## Helper Functions in build.js

| Function | Purpose |
|----------|---------|
| `normalize(text)` | Removes accents and lowercases for comparison |
| `hasKeyword(line, keywords)` | Checks if a line contains any keyword (accent-insensitive) |
| `extractHymn(text)` | Extracts hymn numbers (`#123` format) |
| `extractTime(text)` | Extracts times (`HH:MM` format) |
| `extractScripture(text)` | Extracts Bible references (e.g., `Juan 3:16`) |
| `lookahead(lines, index, maxLines)` | Scans next N lines for a value after a keyword |
| `lookaheadHymn(lines, index)` | Specialized hymn lookahead |

## Important Notes for AI Assistants

- **No tests exist.** There is no testing framework or test suite. If adding tests, `npm test` is not configured in `package.json`.
- **No linter or formatter.** No ESLint, Prettier, or similar tooling is configured.
- **No `.gitignore`.** All files are tracked. Be cautious about generating files that shouldn't be committed (e.g., `node_modules/`).
- **`index.html` is a build artifact** generated by `build.js` — do not edit it directly.
- **Spanish language content:** The bulletin, template, and README are in Spanish. Code comments are in English.
- **The `.docx` format is unpredictable.** Parsing logic must be resilient to formatting variations in the input document (extra spaces, missing fields, accent variations).
- When modifying `build.js`, always verify the build still runs: `npm run build`.
- When modifying `template.html`, ensure all `{{placeholders}}` still match the keys emitted by `build.js`.
